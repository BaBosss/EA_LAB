# W03 — Initial Balance / session IB / extensions

**Strategy design component card / NON_EXECUTABLE / NOT_IMPLEMENTED**
Family: [ARX-01](../families/ARX-01.md). Source locator: `S08 pp.21–22`.
Public descriptions are freshly captured; manual-specific details are carried from the earlier supplied package and require version revalidation before implementation.

## Source-derived mechanism
An opening-range/Initial Balance reference develops and then locks; full-session highs/lows are not IB.

## Proposed EA use — not a frozen trading rule
One independent IB location/event consumer, never an automatic rescue of the closed session experiment.
No parent, instrument, timeframe, entry, exit, risk recipe or trade direction is selected. This is a component design card, not evidence of a complete standalone EA.

## Required semantic freeze
- exchange/broker clock mapping
- duration and first eligible session bar
- range lock and extensions
- short sessions and missing bars

## Proposed deterministic outputs
`ib_high`, `ib_low`, `ib_mid`, `lock_time`. These are **proposed field names**, not an installed schema/API. Bind the final adapter to the existing data conventions before implementation.

## Causal timing and lifecycle
Record source bar/period, `extreme_or_origin_at`, `confirmed_at` and `first_action_at` separately where relevant. A plotted earlier pivot/zone is not an earlier observation. Freeze completed-bar or developing-bar policy, event rearm/expiry, restart behavior and unknown data handling before any consumer runs. Display-only output must not change historical trade decisions.

## Template attachment plan
First build a pure, version/config-bound provider without order calls. For an approved ENTRY role, adapt to `core/entries/IEntry.mqh` and `Entry_Evaluate()` via a separately allocated compile-time wrapper and `core/LabCore.mqh`. For FILTER/CONTEXT, declare exactly which parent decision is affected; no generic filter seam is assumed. EXIT requires its own ownership review. `Stack`, `MoneyManagement`, `Recovery`, `Hedge`, `ExitManager` and `RiskControl` stay unchanged unless explicitly contracted.
Do not copy the existing MA-ordering implementation as K2 event parity; do not invent strength/confidence or reuse a numeric FamilyID.

## Planned targeted checks — NOT RUN

- short/holiday session
- IB differs from full-session range
- Prefix invariance, invalid/warmup data, repeated observation and restart determinism.
- Same input feed/config and exact event-time reference; synthetic checks alone cannot establish TradingView parity.
