# EA Knowledge Query

Search `knowledge/` before broad repo archaeology. For every material answer:

1. identify relevant research/mechanism/regime/validation cards;
2. trace claims to registered `source_id` records;
3. distinguish `SOURCE_CLAIM`, `EA_LAB_INFERENCE`, and `TESTABLE_HYPOTHESIS`;
4. surface contradicting cards or negative knowledge rather than choosing silently;
5. check existing experiment/event evidence when the question asks whether EA_LAB already tested something;
6. say `UNKNOWN` when the source depth does not support a stronger conclusion.

Fast path: use the exact-Git Second Brain Reader index/CLI when available, then check negative memory before
broad archaeology. For an EA problem, preserve EA/variant/build/config/symbol/timeframe/window/data-source fields
(`null` when unknown) and export a read-only packet with pin, hashes, excerpts, draft separation and a
negative-memory `MATCH` or explicit `NO_MATCH`. `DRAFT_NOT_IMPORTED` is not canonical intake.

Use this skill to reduce rediscovery, not to bypass canonical owners. Current project status still comes from `PROJECT_STATE.md`; strategy and experiment truth still come from their existing QI/Factory owners.

Hard boundary: RESEARCH_ONLY. No deployment, trading, risk/default, promotion, owner-attestation, or QI-2+ authority.
