# Price versus return is an empirical feature-choice question, not a default convention

## SOURCE_CLAIM

Kamalov, Gurrib and Rajab compare prior stock price and prior return as inputs for directional movement forecasting. The study uses ten years of data for ten large-cap U.S. companies and four classifiers: logistic regression, random forest, multilayer perceptron and LSTM.

The source reports that price is a more effective standalone input feature than return across the tested classifiers, with the difference particularly visible for LSTM. When technical indicators are added, the performance difference between price and return becomes mixed or substantially reduced.

The paper's motivation is that financial-forecasting feature selection is often subjective even though feature distributions and model optimization can make two related representations behave differently.

## Method / context

- Market / asset: ten large-cap U.S. stocks
- Timeframe / horizon: historical daily stock data; next directional movement classification
- Sample period: ten-year histories used by the study
- Method: LR, RF, MLP and LSTM; price-input versus return-input experiments, with and without technical indicators
- Comparison / benchmark: classifier performance using area under the ROC curve
## Result

In this study, raw price versus return was not interchangeable as a standalone representation. The relative advantage changed after additional technical features were introduced.

## Limitations / caveats

The source notes that its dataset is U.S. individual stocks and explicitly calls for larger datasets covering international markets. Directional-classification performance is not the same as net trading profitability, and the paper does not establish that raw price is universally superior for every asset/model.

## EA_LAB_INFERENCE

Feature choice should be preregistered as a hypothesis and compared by ablation rather than inherited from convention. For any future ML sidecar, `price`, `return`, normalized price and technical features should be treated as alternative representations whose value must be validated on the actual EA asset/timeframe.
