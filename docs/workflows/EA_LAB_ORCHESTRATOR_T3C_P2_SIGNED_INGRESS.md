## Source boundary

The in-memory module imports Node crypto **only**, not file, subprocess, network, scheduler, broker or provider. Every claim must be signed by a pinned public-key identity over an ordered, domain-separated tuple including claim source/owner/resource/lease/time/sequence/idempotency and raw evidence SHA256. The source callback must return exact four-field receipt `{status:'RECORDED_READ_ONLY',scope:'ISOLATED_EVIDENCE_ONLY',can_execute:false,can_submit:false}`; anything else becomes UNKNOWN, never execution permission. ## Real P1 SQLite integration test boundary

`test_orchestrator_signed_claim_ingress.cjs` runs actual ephemeral Ed25519 private-key fixture (generated only at test time), verifies a signed claim and binds its frozen primitive fields to a separate Python OS subprocess. That subprocess opens the previously accepted T3-C-P1 `orchestrator_sqlite_replay_store.py` SQLite WAL+FULL ledger under `os.tmpdir` using an isolated temporary database, commits, and returns actual schema/status receipt. The second identical signed claim is rejected using P1's historical replay tombstone. A strict test-local projection checks the P1 receipt schema/scope and passes only the four permitted fields back to ingress.

**CRITICAL TRUST GAP:** the Python process uses `verify_claim=lambda _:True` deliberately as a SYNTHETIC TEST-CALLBACK. Although the Node test cryptographically verifies its own ephemeral signed fixture before invoking Python, **no authenticated IPC between the two processes and no production issuer/credential root/ACL is established**. A separate caller could invoke the Python fixture without the Node verifier. This proves cross-language isolated data behavior, not a trustworthy production authentication chain. NEVER deploy the fixture as an installed bridge or wire it to live JobControl.
