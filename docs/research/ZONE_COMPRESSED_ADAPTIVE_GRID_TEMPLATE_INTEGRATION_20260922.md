# Zone-Compressed Adaptive Grid — EA Template integration plan

Date: 2026-09-22
Status: DESIGN-ONLY / OWNER-CONCEPT INTAKE / NON-EXECUTABLE
Direct consumer: prospective Boss_23 / LAB_ENTRY_23 implementation contract

## Purpose

Translate the owner's Adaptive Grid + Zone Recovery idea into the existing EA Template V2 without modifying the semantics of existing grid families.

The treatment is not "a smarter DCA add". It is a different exposure lifecycle:

`bull regime -> arm pullback -> virtual grid accrual -> oversold + key support + reversal confirm -> one bounded order -> next-grid exit -> flat/reset`

No real order exists during the virtual-grid accrual stage.

## Why this should not reuse STACK_GRID_AGAINST directly

Current `STACK_GRID_AGAINST` in `ea_template/core/Stack.mqh` adds real positions after adverse distance triggers. That is exactly the intermediate knife-catching the new concept is trying to remove.

Changing mode 92 would alter existing EA semantics. The safe architecture is therefore additive: a new entry-owned strategy running with `STACK_SINGLE`, leaving existing stack modes untouched.

## State machine

### FLAT / DISARMED
Wait for a qualified bullish higher-timeframe regime.

### ARMED
Capture a pullback anchor and spacing. Start a new virtual ladder. No order is sent.

### ACCRUING
As price descends through virtual levels, update `ReachedLevels`. Exposure remains zero.

### ZONE_READY
`ReachedLevels >= MinCompressedLevels` and the structural key-level zone is intersected.

### ENTRY_READY
Bull regime remains active, mean-reversion stretch qualifies and a frozen reversal confirmation fires on final data.

### IN_POSITION
Send one bounded order only. Disable virtual accrual for sizing. Manage only the frozen exit/invalidation and shared risk cage.

### RESET
After full flat or pre-entry invalidation, clear anchor, reached levels, zone identity and finality state before re-arming.

## Mathematical exposure comparison

Let a conventional equal-lot grid have rung prices `P1..Pn` and per-rung quantity `q`.
Its final notional quantity after n fills is `Q = n*q` and its volume-weighted average entry is:

`VWAP_grid = (P1 + ... + Pn) / n`

A compressed entry that waits for deep level `Pc` and then enters `Q` has average entry `VWAP_compressed = Pc`.

When `Pc < VWAP_grid` for a long trade, the compressed entry has a lower cost basis and zero market exposure during the descent from P1 to Pc. That can reduce time-underwater and path drawdown before entry.

It does **not** prove lower terminal or maximum drawdown: after entry the compressed trade immediately carries Q. If price continues through the support zone, its loss slope is Q from the first adverse tick after entry.

Therefore the design must be evaluated against both exposure benefit and zone-failure concentration risk.

## Required one-change comparator

Baseline and treatment must share:

- same symbol and installation lineage;
- same test window/model;
- same bull-regime definition;
- same anchor and spacing;
- same maximum virtual levels and maximum notional;
- same key-level and invalidation rules;
- same execution costs and shared risk cage;
- same next-grid target logic where mechanically comparable.

Primary planned difference:

- baseline physically fills each reached rung;
- treatment records the same rungs virtually and physically enters once after the recovery gates qualify.

If a secondary experiment changes confirmation or sizing, it becomes a separate preregistered cell rather than being folded into the same comparison.

## Risk invariants

1. `requested compressed notional <= comparator maximum notional`.
2. Existing hard-kill, max-lot, deposit-load and order guards remain authoritative.
3. Failure to price/normalize/cage the requested aggregate lot means SKIP; not split/rescue.
4. V0 does not add recovery, hedge, martingale or post-entry averaging.
5. No optimization is allowed to increase max notional beyond the frozen comparator.
6. No short-side symmetry is inferred from the long concept.

## Finality / anti-lookahead

All regime, Z-score, structure and reversal decisions must use closed/final bars unless the executable contract explicitly proves an intrabar requirement. Confirmed pivots must respect right-bar confirmation; a later-known swing cannot be backfilled as if it were known at the decision time.

The support identity used for an entry must be recorded in the result evidence so the test can prove which pivot/zone was actually available at that timestamp.

## Metrics that matter

In addition to the normal report schema, record treatment-specific fields:

- virtual levels reached;
- virtual comparator VWAP;
- compressed fill price;
- entry-price improvement in points / ATR;
- time flat while baseline was exposed;
- exposure-lot-seconds or equivalent time-weighted exposure;
- MAE after physical entry;
- support break distance after entry;
- missed baseline winners;
- compressed entries that fail before reaching next grid;
- realized versus maximum allowed exposure.

## Research ladder after source acceptance

A future test contract should start with deterministic unit/state-machine tests and compile/regression. Only after executable source is accepted should a fixed Model1 MAIN+BWD screen be opened under the current EA_RND protocol. No Model4, optimization or HOLDOUT follows automatically.

The first research question is narrow:

> With identical maximum notional and grid geometry, does delaying physical exposure until the recovery zone improve path risk without destroying participation?

That question can be falsified. A result with lower DD but an unacceptable missed-trade/participation collapse is not automatically a success.
