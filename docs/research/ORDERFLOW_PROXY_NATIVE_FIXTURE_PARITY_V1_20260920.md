## Receipt and controller trust boundary

`parse_native_ledger.py` does not accept a journal and expected ledger by themselves. Before comparison it requires a separately frozen safe-runner/controller receipt plus independently frozen controller evidence whose SHA-256 is supplied out of band. The independently trusted controller evidence, not the receipt, pins the receipt digest, exact reviewed bridge source head, runtime-contract ID, and package-manifest digest.

The receipt binds the terminal and tester configuration identities and exact bytes, EA source, EX5, generated MQL include, expected ledger, accepted fixture and source graph, package manifest, and exact journal bytes. The parser validates every supplied byte sequence against those bindings and validates the generated package manifest and expected-ledger structure internally before it compares cases.

This is deliberately a narrow input-validation boundary, not cryptographic machine attestation. Matching self-supplied names, prefixes, booleans, hashes, a receipt, or a controller-evidence-shaped JSON file does not prove that MetaTrader executed. The parser cannot mint controller authority. Its native-execution result is valid only when the caller independently froze and authenticated the controller-evidence digest outside the parser invocation. Supplying a digest computed from an arbitrary receipt/evidence pair as part of the same untrusted flow invalidates the authority claim even if byte checks pass.

Tests generate only `FIXTURE_ONLY_INTEGRITY_CONTROL` evidence. A successful test control is returned as `FIXTURE_ONLY_CONTROLLER_RECEIPT_SHAPE_INTEGRITY / FIXTURE_INTEGRITY_PASS / native_execution_qualified=false / execution_status=NOT_EXECUTED`; it can never be reported as actual native execution. There is currently no actual controller runtime receipt, so the project execution status remains `NOT_EXECUTED`.

After that trust chain validates, comparison rejects:

- missing, duplicate or extra cases;
- an absent or duplicate completed sentinel;
- wrong fixture or source-graph hash;
- an unknown, placeholder or mismatched frozen runtime-contract ID or reviewed bridge source head;
- a wrong receipt, package manifest, expected ledger, journal, EX5, generated include, EA source, terminal configuration, or tester configuration;
- a receipt digest not pinned by the independently frozen controller evidence;
- malformed JSON fields or types, including booleans masquerading as integers;
- generated/unknown native origin;
- wrong variant, status, replay-return relation, direction, current-bar identity, setup/trigger time, geometry or proxy/profile identity;
- a malformed or extra native field.

Floating representations are compared as exact fixed-decimal strings at 12 decimal places. There is no range tolerance or `isclose` allowance. A difference at the twelfth decimal place fails, while ordinary Python/MQL binary64 display noise below that serialization precision cannot create a false mismatch. This precision is far below any frozen branch threshold or fixture price increment and cannot conceal a branch or geometry change.

Only independently pinned controller evidence with scope `ACTUAL_NATIVE_EXECUTION` can produce parser `PASS`, named `SYNTHETIC_FIXTURE_NATIVE_PARITY_ONLY`. The scope string itself is not authority; the external controller-evidence digest is the trust root. A material difference is `FAIL` and must not be repaired by mutating the accepted OFP components, reference, fixture or thresholds.
