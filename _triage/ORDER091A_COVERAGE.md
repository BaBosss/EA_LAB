## Anomalies

1. **BOM-less UTF-16 encoding bug (found + fixed this order):** 374 of the 542 new sources are
   UTF-16 LE **without BOM** (MetaEditor save variant). `read_text()` in `scripts/fxdreema_xray.py`
   only detected UTF-16 by BOM, so these decoded as NUL-interleaved garbage -- every regex
   (including the `fxdreema` signature check) silently matched nothing. **This is why the
   ORDER-074 drive-wide scan never saw them** (not a path-coverage gap -- an encoding gap).
   Fixed with a NUL-density heuristic in `read_text()`; the first 091A pass was rolled back and
   rerun. After the fix, exactly those 374 files parse as full fxDreema block cards (the other
   168 new files are genuinely non-fxDreema hand-written/AI-generated sources).
2. **User per-folder counts reconcile almost exactly** once file types are accounted for:
   - BOT MOGUL "~713 reports" = 711 .html + 2 .pdf (pdf not inventoried -- reports CSV covers htm/html/set only)
   - .Final EA "~389 reports" = 23 .html + 350 .set + 16 .pdf (same pdf note)
   - `3. ready to use`: 103 bin found vs "~102" (off by 1) · all other folders match exactly
3. **`review EA\Jobot` = 1,556 binaries, zero sources, zero cross-duplicates** -- all 1,556 hashes
   unique, none matched anywhere else in the scan. Wave-3 strings-analysis is the only intake path.
4. Only **1 new-unique source** in all of BOT MOGUL (2,905 binaries, 3 src) and **0** overlap between
   its binaries and other folders except its own two unscanned duplicate copies -- vendor bundle is
   binary-only as expected.
5. 137 of the 542 new rows have `n_inputs=0`; most are course exercises/snippets or API-test
   scripts (e.g. `.Final EA\Day3 AI Trading Agent\*` = OpenAI WebRequest experiments, flagged
